# Tasks: Extended Agent Capabilities

**Input**: Design documents from `/specs/003-extended-capabilities/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md, `.specify/memory/constitution.md` (v1.0.0); completed specs `001-core-pr-steward` and `002-multi-agent-safety` (verified in Phase 0)

**Tests**: Included. The constitution requires tests (Principle I) and a conformance suite that runs in CI against every implementation (Principle IX); the spec makes the conformance suite a deliverable (FR-022, spec 001).

**Organization**: Tasks are grouped by user story. Story numbers and task IDs T110-T141 are those of the original single feature; new tasks use the reserved range T300-T399. Phase numbers restart in this spec. There is no Setup phase (no new component is scaffolded) and the Foundational phase holds the one migration and the harness additions. Phase 0 (reconcile) is mandatory and blocks everything else.

## Format: `- [ ] T### [P?] [US#?] Description with file path`

- **[P]**: can run in parallel with the other [P] tasks in the same step (different files, no dependency on an incomplete task). Where a step lists four tasks (one per implementation), the four are [P] with each other; steps within a phase run in the order listed.
- **[US#]**: user story from spec.md. Phase 0, Foundational, and Polish tasks have no story label.
- **⚠ needs owner approval**: task creates or destroys AWS resources, pushes images, writes to GitHub with the owner's token, or spends money on live model calls. Stop and get explicit approval (with `tofu plan` output shown for infrastructure) before doing it. Everything else is local and safe.

## Path Conventions

Per plan.md: `implementations/<name>/` (Python: `src/steward/`, TypeScript for Mastra: `src/`), `shared/conformance/`, `shared/db/`, `infra/{durable,modules,implementations/<name>}/`, `specs/003-extended-capabilities/spikes/`. Spec 001 paths (`docs/`, `justfile`, `compose.yaml`) are used but not created here.

## Constraints that apply to every task

- **No shared agent logic across frameworks** (constitution, Code Quality Gates): shared code is limited to the contract, fixtures, database migrations, stubs, tool server, conformance harness, and OpenTofu modules. Retrieval, MCP serving, grants, memory, sandbox, and A2A are written per framework in its own idiom.
- **Framework facts come from current docs**, not memory (research.md marks UNVERIFIED items as spikes S1, S5, S6, S7, S9, S13). Record surprises in the component's `CLAUDE.md`.
- **Definition of done for any implementation task**: tests written and passing, `ruff check` (Python) or `tsc --noEmit` (TypeScript) clean, and the exact commands and output recorded. Reports of "validated" without commands are not accepted (Constitution VIII).
- **Model access uses each framework's maintained Bedrock client** (`langchain-aws`, Claude Agent SDK Bedrock mode, `@ai-sdk/amazon-bedrock`, `pydantic-ai-slim[bedrock]`), never a hand-rolled `boto3` `invoke_model` wrapper (Constitution VII). A capability the client lacks is recorded as "not supported on Bedrock" (FR-023, FR-024) and appended to spec 001 `research.md` §6, not worked around and not routed to the Anthropic API.
- **Secrets**: credentials and peer tokens come from the environment, an AWS profile, or Secrets Manager only and are never written to any file in the repository (Constitution V). Nothing secret is given to a sandbox.
- **Untrusted data**: retrieved content, remembered content, and remote-specialist input are untrusted (FR-014, spec 002); reuse the implementation's existing untrusted-data wrapper and secret scrubber rather than adding new ones.
- **Independent verification**: a second actor (CI or a fresh worktree/session) reproduces each finished component's tests (Constitution I).
