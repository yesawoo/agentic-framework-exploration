# Tasks: Multi-Agent and Safe Interaction

**Input**: Design documents from `/specs/002-multi-agent-safety/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/ (`http-api-additions.yaml`, `work-queue-amendments.md`), quickstart.md, `.specify/memory/constitution.md` (v1.0.0), and a completed spec 001 (`specs/001-core-pr-steward/`)

**Tests**: Included. The constitution requires tests (Principle I) and a conformance suite that runs in CI against every implementation (Principle IX); the spec makes the conformance suite a deliverable (FR-022).

**Organization**: Tasks are grouped by user story. Stories keep their numbers from the original spec (US4-US7). Phase numbers restart in this spec: Phase 0 reconcile, Phase 1 foundational delta, Phases 2-5 the stories, Phase 6 polish. Task IDs are the original IDs (T080-T109) for tasks carried over, and T200-T222 for new tasks in this spec's reserved range (T200-T299). Two carried-over tasks changed scope (see "Scope changes" at the end).

## Format: `- [ ] T### [P?] [US#?] Description with file path`

- **[P]**: can run in parallel with the other [P] tasks in the same step (different files, no dependency on an incomplete task). Where a step lists four tasks (one per implementation), the four are [P] with each other; steps within a phase run in the order listed.
- **[US#]**: user story from spec.md. Reconcile, Foundational, and Polish tasks have no story label.
- **⚠ needs owner approval**: task creates or destroys AWS resources, writes to GitHub with the owner's token, or spends money on live model calls. Stop and get explicit approval (with `tofu plan` output shown for infrastructure) before doing it. Everything else is local and safe.
- "spec 001 T034" style references point at a task, file, or contract in the predecessor spec dir `specs/001-core-pr-steward/`.

## Path Conventions

Per plan.md: `implementations/<name>/` (Python: `src/steward/`, TypeScript for Mastra: `src/`), `shared/conformance/`, `shared/db/`, `specs/002-multi-agent-safety/` (spikes in `spikes/`). No new component and no new infrastructure root.

## Constraints that apply to every task

- **No shared agent logic across frameworks** (constitution, Code Quality Gates): shared code is limited to the contract, fixtures, database migrations, stubs, conformance tests, and OpenTofu modules.
- **Framework facts come from current docs**, not memory (research.md marks UNVERIFIED items as spikes). Record surprises in the component's `CLAUDE.md`.
- **Definition of done for any implementation task**: tests written and passing, `ruff check` (Python) or `tsc --noEmit` (TypeScript) clean, and the exact commands and output recorded. Reports of "validated" without commands are not accepted (Constitution VIII).
- **Model access uses each framework's maintained Bedrock client** (`langchain-aws`, Claude Agent SDK Bedrock mode, `@ai-sdk/amazon-bedrock`, `pydantic-ai-slim[bedrock]`), never a hand-rolled `boto3` `invoke_model` wrapper (Constitution VII). A capability the client lacks is recorded as "not supported on Bedrock" (FR-023, FR-024) and appended to spec 001 research §6 (task T220), not worked around and not routed to the Anthropic API.
- **Secrets**: credentials come from the environment or an AWS profile only and are never written to any file in the repository (Constitution V).
- **Independent verification**: a second actor (CI or a fresh worktree/session) reproduces each finished component's tests (Constitution I).
- **Do not edit spec 001 artifacts.** Deviations found in Phase 0 are recorded in `reconciliation.md` and fixed in this spec's artifacts. A defect in 001 that blocks this spec becomes an open question for the owner.
